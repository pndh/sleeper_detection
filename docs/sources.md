## 1. Sleeper Attack (Li et al.)

- Paper: https://arxiv.org/abs/2605.28201
- Repo (anonymous review mirror): https://anonymous.4open.science/r/skdvnfu23ihr9wdscnksf1asdffsaef
- Local copy: `data/sleeper_attack/` (12 dataset JSONs, upstream README, `SHA256SUMS`, `PROVENANCE.txt`).
  Made because an anonymous mirror can be taken down after review.
- Download one file (the browse API refuses subfolder listings, direct file paths work):
  ```
  curl -L https://anonymous.4open.science/api/repo/skdvnfu23ihr9wdscnksf1asdffsaef/file/datasets/<strategy>/<state>.json
  ```

**Contents verified**
- 1,896 cases total, matching the paper. Per strategy: LIP 162, PIE 162, PIC 150 cases in each of
  `session`, `memory`, `skill`, and `single` (the direct single-turn baseline).
- Record fields: `case_id, meta_info, visible_tools, harmful_goal_categories, harmful_goal, attack_type,
  single_injection, harmful_tools, eval_config, target_tool_actions, turns, memory_init, memory_template_case_id`.
- `eval_config` is an ordered tool-trace check, e.g. MemoryUpdate(append, contains payload) then
  MemoryRetrieve then the harmful tool call. Usable directly as the ASR oracle for PLAN M1e.
- Not downloaded yet: `results/`, `defense/`, `skill_data/`, `src/`, `run_batch.py`.

**Issues for the plan**
- **Tools are LLM-simulated, not AgentDojo.** `config.py` sets a `SIMULATOR_MODEL` (default deepseek-v3.2)
  that fabricates tool outputs. Tool names (262 distinct, e.g. `SlackManageMembership`, `ShopifyDeleteProduct`)
  come from the InjecAgent/ToolEmu toolkit, which is also in ~/InjecAgent. PLAN §3 needs fixed tool outputs,
  so the simulator must be replaced by cached or scripted outputs, or cases must be ported onto AgentDojo tools.
- **Only 1 or 2 turns per case** (plant turn then trigger turn; 1,422 two-turn, 474 one-turn). There are
  no benign turns in between. PLAN §3's 1-20 benign queries have to be generated by us.
  The paper's PIC turn sweep (1,3,5,8,12,20) exists only as results, not as extra datasets.
- **Plant is live, not pre-seeded.** Most cases expect the agent itself to write the payload
  (MemoryUpdate / SkillUpdate) during turn 1. PLAN §2 assumes the payload is already in the store.
  `memory_init` gives the clean starting store, so a pre-seeded poisoned store can be built from it plus
  the payload text, but that is a port and must be reported as one (PLAN §6 limitations).
- **Outcome labels are not the paper's clean six.** `attack_type` has 8 values
  (e.g. `Memory Poisoning` 600, `Sensitive Info Leakage` 8). Needs a mapping before stratifying.
- **License is unclear.** CC BY 4.0 covers the paper. The repo has no LICENSE. Ask the authors before
  redistributing the data in the M5 release.

## 2. Explosive prompts (Szczepaniak et al.)

- Paper: https://arxiv.org/abs/2609.22510 (posted 11 days before this check)
- No code, payload set, or DeFuse detector release found: no links in the paper text, no GitHub search hits.
- **Directly relevant:** the paper runs real multi-turn episodes on AgentDojo's four suites (banking, slack,
  travel, workspace), with triggers in three families (conversational closings like "thanks"/"bye",
  agentic-verb cues, meta references). It also evaluates Meta-SecAlign-70B on paired AgentDojo episodes.
- **Per PLAN M0 this is a stop-and-report item.** Options: email the authors for the payload set; or
  re-create payloads from the paper's description and appendix, labelled as a reconstruction.
  Leave-one-source-out (PLAN M3d) depends on this.

## 3. Sleeper memory poisoning (Pulipaka et al.)

- Paper: https://arxiv.org/abs/2605.15338 . Repo: https://github.com/ivaxi0s/LLM-agent-memory-poisoning
  (last push 2026-07-26).
- Repo has `datasets/{released,builders,downstream,provenance,smoke}`, attack prompts, and `sleeper_eval`.
- Not built on AgentDojo. No license, so default copyright applies.
- Not required by PLAN (listed as context), but it is a possible third payload source for
  leave-one-source-out if explosive prompts stay unavailable.
